# Сеть

Проверено запуском на `20261112-d608e3a-stock` и `20261112-c64186e-cpma`, а там, где это сказано, и на [OSP](../glossary.md#osp) `20261114-9e899840-osp`.

## Соединения

| Соединение | Направление | Что открыть | Признак, что работает |
|---|---|---|---|
| [Агент комнаты](../glossary.md#агент-комнаты) → адрес публикации из [`CLOUD_BASE_URL`](env.md#cloud_base_url) | исходящее HTTPS | если исходящие соединения ограничены, разрешите HTTPS к этому адресу; по умолчанию `https://cloud.js-dos.com` | карточка [комнаты](../glossary.md#комната) есть в лобби |
| Сервер → peer-сервер (`NET_PEER_SERVER`, `wss://net.js-dos.com:444`) | исходящее WSS, TCP 444 | ничего, если исходящие не закрыты | в логе `Alias "room.q3ded.<…>" registration confirmed for peer <N>` |
| Браузерный игрок → сервер | WebRTC через peer-сервер | ничего | в логе `ClientBegin: <N>` |
| [Обычный клиент](../glossary.md#обычный-клиент) Q3 → сервер | входящее UDP на `PORT` | UDP `PORT` в firewall [хоста](../glossary.md#хост) и на роутере; при подключении через сетевой мост Docker (bridge) ещё `ports:` с тем же номером | внешний [`getstatus`](../glossary.md#getstatus) отвечает `statusResponse` |
| Сервер → [мастер-серверы](../glossary.md#мастер-сервер) | исходящее UDP (по умолчанию порт 27950) | ничего, если исходящие не закрыты | сервер есть в ответе мастера на `getservers` |

Браузерному игроку входящие порты не нужны. При проверке браузерный игрок вошёл на сервер в [контейнере](../glossary.md#контейнер) с сетью bridge, до которого UDP снаружи не доходил.

Обычным клиентам нужен `NATIVE_UDP=1`. При `NATIVE_UDP=0` сервер не открывает UDP-сокет вообще: в логе `Native UDP families: 0`, строки `Opening IP socket` нет, `getstatus` не отвечает даже с самого хоста. Комната при этом регистрируется, браузерные игроки входят.

## Состояния сервера и их признаки

| Состояние | Признак | Что это не доказывает |
|---|---|---|
| Контейнер запущен | `docker compose ps`: `running` | что [entrypoint](../glossary.md#entrypoint) прошёл проверки: при [отказе](../glossary.md#отказ-при-старте) контейнер сразу выходит с кодом 1 |
| [Движок](../glossary.md#ioq3ded) загрузил карту | в логе `Starting ioq3ded: mode=… map=…`, затем `Server: <карта>` | что комната видна |
| Сервер зарегистрирован на peer-сервере | `registration confirmed` в логе | что комната есть в лобби: при `RUN_ROOM_AGENT=0` строка есть, комнаты нет |
| Комната опубликована в лобби | карточка комнаты в [лобби](../glossary.md#лобби) | что сервер доступен извне по UDP |
| Браузерный игрок вошёл | `ClientBegin: <N>` в логе | что войдёт обычный клиент |
| Обычный клиент видит сервер извне | `getstatus` с другой машины отвечает `statusResponse` | |

`registration confirmed` и строка `Opening IP socket: 0.0.0.0:<PORT>` показывают, что сервер работает локально. Доступность извне доказывает только запрос с другой машины.

## Как проверить

Внешний `getstatus` отправляйте с машины вне сети сервера:

```sh
python3 -c 'import socket,sys; s=socket.socket(2,2); s.settimeout(3); s.sendto(b"\xff"*4+b"getstatus x",(sys.argv[1],int(sys.argv[2]))); print(s.recv(65535)[4:].decode("latin-1"))' SERVER_IP 27960
```

Ответ начинается с `statusResponse` и содержит `\sv_hostname\…\mapname\…`. Тайм-аут (`socket.timeout`) значит, что UDP не доходит.

## Обычный клиент не видит сервер

Комната в лобби есть, а обычный клиент сервер не находит. Проверяйте по порядку:

1. `NATIVE_UDP=1` в `compose.yaml`. В логе должно быть `Native UDP families: 1` и `Opening IP socket: 0.0.0.0:<PORT>`.
2. `PORT` и обе стороны `ports:` задают одно и то же число, протокол `/udp`.
3. Если `getstatus` с самого хоста (`127.0.0.1`) отвечает, а с другой машины приходит тайм-аут, пакеты режет firewall хоста или роутер. Откройте UDP `PORT`.
4. Firewall хоста может отбрасывать трафик, который Docker пробрасывает в сеть bridge, даже при открытом порте. Признак тот же: с хоста сервер отвечает, снаружи приходит тайм-аут. Варианты решения: правило firewall для проброшенного трафика или [сеть хоста](../glossary.md#сеть-хоста) (ниже).

## Сеть хоста

Рабочие серверы тестового [стенда](../glossary.md#стенд) разработчиков DosZone запускаются с `network_mode: host` без `ports:`, то есть контейнер работает в сети хоста. Сервер слушает `PORT` прямо на хосте, и firewall хоста должен пропускать UDP `PORT`. Примеры справочника используют сеть bridge и `ports:`.

## Мастер-серверы

| [ENV](env.md) | Значение |
|---|---|
| `PUBLISH_Q3_MASTER` | `1`: публиковать сервер в мастер-серверах; требует `NATIVE_UDP=1` |
| `Q3_MASTERS` | до пяти адресов `host[:port]` через пробел; не задан: `directory.ioquake3.org:27950`, пусто: без мастеров; проверено запуском по значениям `sv_master1` … `sv_master5` |

Рабочий сервер с публикацией нашёлся во всех шести опрошенных мастерах: `master.ioquake3.org`, `directory.ioquake3.org`, `master.quake3arena.com`, `master0.excessiveplus.net`, `dpmaster.deathmask.net`, `master.maverickservers.com`. Серверов с `PUBLISH_Q3_MASTER=0` там нет.

## IPv6

`NATIVE_IPV6=1` включает IPv6 только для обычных клиентов (`net_enabled 3`) и требует `NATIVE_UDP=1`. Браузерных игроков это не касается. Адрес задаёт `NATIVE_BIND6` (по умолчанию `::`). Вживую не проверялось.

## Занятый порт

Если `PORT` уже занят, сервер останавливается с кодом 3 уже после регистрации комнаты:

```
WARNING: NET_IPSocket: bind: Address already in use
Unable to bind requested native UDP endpoint (no port fallback)
```

Entrypoint порт заранее не проверяет. Другой сервер на этом порту продолжает работать.
