# Термины и определения

Термины идут по алфавиту: сначала записанные латиницей, затем русские. У каждого термина короткое определение и ссылка на раздел, где он объяснён подробно.

## Латиница

### alias

Адрес [комнаты](#комната) в [лобби](#лобби) вида `room.q3ded.<суффикс>`. Его задаёт [ENV](#env) `NET_SERVER_NAME`, и у каждого сервера суффикс свой.

Подробно: [NET_SERVER_NAME](common/env.md#net_server_name).

### archive-переменная

[Переменная сервера](#переменная-сервера), которую [движок](#ioq3ded) сохраняет в [`q3config_server.cfg`](#q3config_servercfg): переменная с флагом `A` в `cvarlist` или заданная командой `seta`. Значение такой переменной, заданное через [rcon](#rcon), переживает [рестарт](#рестарт-контейнера) и [пересоздание контейнера](#пересоздание-контейнера), если при старте его никто не задаёт заново.

Подробно: [q3config_server.cfg](common/layers.md#q3config_servercfg).

### `autoexec.cfg`

Файл настроек оператора, который [движок](#ioq3ded) выполняет при старте после `default.cfg` и [`q3config_server.cfg`](#q3config_servercfg). В примерах он лежит рядом с `compose.yaml` и [смонтирован](#смонтированный-файл) в `/opt/q3-data/<мод>/autoexec.cfg`. [Командная строка сервера](#командная-строка-сервера), [конфиг мода](#конфиг-мода) и [режим мода](#режим-мода) применяются позже, и заданные ими значения перекрывают строки этого файла.

Подробно: [Какой файл читается](common/layers.md#какой-файл-читается).

### CPM

[Физика игры](#физика-игры) [CPMA](#cpma) по умолчанию: `GAMEPLAY` не задан или равен `cpm`, в [`getstatus`](#getstatus) видно `server_gameplay CPM`. Вторая физика CPMA называется [VQ3](#vq3).

Подробно: [Физика VQ3 в CPMA](recipes/cpma-vq3.md).

### CPMA

[Образ](#образ) с [модом](#мод) CPMA 1.53, [каталог игры](#каталог-игры) `cpma`. Только у него есть пресеты ([`PRESET`](#preset)) и две [физики](#физика-игры) (`GAMEPLAY`), и только он требует явно заданный `NET_PEER_SERVER`.

Подробно: [CPMA](cpma/README.md).

### digest

Идентификатор образа по содержимому, строка `sha256:…`. Примеры указывают образ по digest (`image: ghcr.io/doszoner/q3ded@sha256:…`), а [тег](#тег) записывают в комментарии строкой выше.

Подробно: [Образы](README.md#образы).

### entrypoint

Скрипт `/app/entrypoint.sh`, с которого начинается [контейнер](#контейнер). Он проверяет [ENV](#env). При ошибке он печатает [отказ](#отказ-при-старте) и выходит с кодом 1, а если ошибок нет, запускает [ioq3ded](#ioq3ded) с [командной строкой](#командная-строка-сервера) из ENV и [зашитых значений](#зашитое-значение) и, при `RUN_ROOM_AGENT=1`, [агент комнаты](#агент-комнаты).

Подробно: [Компоненты контейнера](common/container.md#компоненты).

### ENV

Переменные окружения контейнера, например `MODE` или `HOSTNAME`. Их задают в `environment:` сервиса в `compose.yaml`, [entrypoint](#entrypoint) читает их при старте контейнера, а изменённый ENV применяет только [пересоздание контейнера](#пересоздание-контейнера), не [`docker compose restart`](#рестарт-контейнера).

Подробно: [ENV](common/env.md).

### `fs_basepath`

Переменная [движка](#ioq3ded) со значением `/opt/q3-data`: каталог с файлами игры и мода из образа, только для чтения. Сюда же монтируют свой [`autoexec.cfg`](#autoexeccfg).

Подробно: [Какой файл читается](common/layers.md#какой-файл-читается).

### `fs_homepath`

Переменная [движка](#ioq3ded) со значением `/data/home`, это [том home](#том): домашний каталог движка, куда сервер пишет свои файлы, например [`q3config_server.cfg`](#q3config_servercfg). Файл здесь скрывает одноимённый файл из `/opt/q3-data`.

Подробно: [Какой файл читается](common/layers.md#какой-файл-читается).

### `getstatus`

Запрос по [UDP](#udp) на порт сервера. Сервер отвечает строкой `statusResponse` со своими переменными (`sv_hostname`, `mapname` и другими). Ответ на запрос с другой машины доказывает, что [обычный клиент](#обычный-клиент) видит сервер.

Подробно: [Как проверить](common/network.md#как-проверить).

### `InitGame`

Строка лога, которую игра пишет при загрузке карты. У [OSP](#osp) при старте таких строк две: примерно через 1,8 с после первой загружается [режим OSP](#режим-мода) и перезапускает карту.

Подробно: [Кто кого перекрывает](common/layers.md#кто-кого-перекрывает).

### instagib

Значение [`PRESET`](#preset) у CPMA. Оно допустимо при `MODE` ffa, tdm, ctf и ftag, и для них [entrypoint](#entrypoint) выбирает [режимы мода](#режим-мода) `DZIFFA`, `DZITDM`, `DZICTF` и `DZIFT`.

Подробно: [PRESET](common/env.md#preset).

### ioq3ded

Программа выделенного сервера ioquake3 (`/app/ioq3ded.x86_64`), процесс, который ведёт игру. В справочнике её называют движком. [Entrypoint](#entrypoint) запускает её с [командной строкой сервера](#командная-строка-сервера).

Подробно: [Компоненты контейнера](common/container.md#компоненты).

### `map_restart`

Команда [консоли](#консоль-сервера) и [rcon](#rcon), которая перезапускает текущую карту. Контейнер при этом работает дальше, [ENV](#env) и [зашитые значения](#зашитое-значение) не меняются.

Подробно: [Жизненный цикл настройки](common/layers.md#жизненный-цикл-настройки).

### OSP

Образ с модом OSP 1.03a, [каталог игры](#каталог-игры) `osp`. Лимит игроков всегда 14, лимиты матча задаёт [режим OSP](#режим-мода), а `maplist.txt` образ не читает.

Подробно: [OSP](osp/README.md).

### peer-сервер

Сервер из [ENV](#env) `NET_PEER_SERVER` (адрес `ws://host[:port]` или `wss://host[:port]`, для dos.zone `wss://net.js-dos.com:444`), с которым выделенный сервер держит соединение. На нём сервер регистрирует свой [alias](#alias) (строка `registration confirmed`), а через него идёт согласование соединения (signaling), по которому [браузерные игроки](#браузерный-клиент) подключаются по [WebRTC](#webrtc).

Подробно: [Соединения](common/network.md#соединения).

### PK3

Архив ZIP с файлами игры: картами, текстурами, конфигами. [Движок](#ioq3ded) ищет нужный файл и отдельным файлом, и внутри PK3. Свои PK3 принимает только [stock](#stock), и для них предусмотрен каталог `/data/custom/demoq3`.

Подробно: [Какой файл читается](common/layers.md#какой-файл-читается), [Свои карты stock](recipes/stock-custom-maps.md).

### `PRESET`

[ENV](#env) CPMA, который выбирает вариант режима: `classic` (по умолчанию), [`instagib`](#instagib), `rocket-only`, `bfg-only`, `gauntlet-only`. При `classic` [entrypoint](#entrypoint) передаёт в `mode_start` имя режима CPMA, например `FFA`, а при остальных значениях режим `DZ…` из `/opt/q3-data/cpma/modes/`. `instagib` допустим при `MODE` ffa, tdm, ctf, ftag, а `rocket-only`, `bfg-only` и `gauntlet-only` только при `MODE=ffa`. У stock и OSP допустим только `classic`.

Подробно: [PRESET](common/env.md#preset).

### `q3config_server.cfg`

Файл `/data/home/<мод>/q3config_server.cfg`, который пишет сам [движок](#ioq3ded), в нём хранятся [archive-переменные](#archive-переменная). Движок читает его при следующем старте до [`autoexec.cfg`](#autoexeccfg), вручную его не создают.

Подробно: [q3config_server.cfg](common/layers.md#q3config_servercfg).

### rcon

Удалённая консоль: команды серверу по [UDP](#udp) с паролем `rconPassword`, который задают в [`autoexec.cfg`](#autoexeccfg). Нужен `NATIVE_UDP=1`, а при пустом пароле сервер rcon не принимает.

Подробно: [rcon](recipes/rcon.md).

### `rtc.json`

Файл `/data/run/rtc.json`. При `RUN_ROOM_AGENT=1` его на каждом старте пишет [агент комнаты](#агент-комнаты), а [entrypoint](#entrypoint) ждёт его до `RTC_WAIT_SECS` секунд и только потом запускает [ioq3ded](#ioq3ded). При `RUN_ROOM_AGENT=0` файл должен уже лежать в [томе](#том) и быть непустым. К сообщениям об ошибке этот файл не прикладывают.

Подробно: [Файлы, которые создаёт и удаляет сервер](common/container.md#файлы-которые-создаёт-и-удаляет-сервер).

### `status.json`

Файл `/data/run/status.json`: его пишет сервер, а читает [агент комнаты](#агент-комнаты). Через него в [лобби](#лобби) попадают имя сервера из `HOSTNAME` и адрес картинки (поле `image`).

Подробно: [Файлы, которые создаёт и удаляет сервер](common/container.md#файлы-которые-создаёт-и-удаляет-сервер).

### stock

Образ обычного Quake III (ioquake3), [каталог игры](#каталог-игры) `demoq3`. Из трёх образов только он принимает свои карты в [PK3](#pk3).

Подробно: [stock](stock/README.md).

### `sv_pure`

[Зашитая переменная](#зашитое-значение), от которой зависит проверка файлов: при `sv_pure 1` (stock и OSP) клиент проверяет все [PK3](#pk3) образа, у CPMA значение `0`.

Подробно: [Файлы игры: результат](recipes/game-files.md#результат).

### UDP

Сетевой протокол, который передаёт данные отдельными пакетами, без установки соединения. По UDP на `PORT` с сервером играет [обычный клиент](#обычный-клиент), по UDP идут [`getstatus`](#getstatus), [rcon](#rcon) и обмен с [мастер-серверами](#мастер-сервер).

Подробно: [Соединения](common/network.md#соединения).

### VQ3

Вторая [физика игры](#физика-игры) CPMA, её включает `GAMEPLAY: "vq3"`. Чем физики различаются в игре, показано в рецепте.

Подробно: [Физика VQ3 в CPMA](recipes/cpma-vq3.md).

### `vstr`

Команда движка, которая выполняет команды, записанные в значении переменной. У [stock](#stock) на ней построена ротация карт: `+vstr rotate1` выполняет команды из переменной `rotate1`.

Подробно: [Ротация карт: stock](recipes/rotation.md#stock).

### WebRTC

Способ обмена данными в реальном времени, который встроен в браузер. По WebRTC [браузерный клиент](#браузерный-клиент) соединяется с выделенным сервером, а договариваются о соединении они через [peer-сервер](#peer-сервер).

Подробно: [Соединения](common/network.md#соединения).

### WSS

Защищённое соединение WebSocket, адрес которого начинается с `wss://`. По WSS выделенный сервер держит исходящее соединение с [peer-сервером](#peer-сервер) dos.zone `wss://net.js-dos.com:444` (TCP 444).

Подробно: [Соединения](common/network.md#соединения).

## Русские термины

### Агент комнаты

Второй процесс контейнера рядом с [ioq3ded](#ioq3ded): `dedicated_room_agent` из `/app`. Он публикует [комнату](#комната) в [лобби dos.zone](#лобби), пишет [`/data/run/rtc.json`](#rtcjson) и читает [`/data/run/status.json`](#statusjson), который пишет сервер. При `RUN_ROOM_AGENT=0` агент не запускается.

Подробно: [Компоненты контейнера](common/container.md#компоненты).

### Браузерный клиент

Quake III в браузере. Игрок запускает его из [лобби](#лобби), а соединение с сервером идёт по [WebRTC](#webrtc) через [peer-сервер](#peer-сервер). Браузерному игроку входящие порты не нужны.

Подробно: [Соединения](common/network.md#соединения), [Браузерный вход в OSP](osp/README.md#браузерный-вход).

### Готовность

Отметка игрока, что он готов к матчу, командой `\ready`. В CPMA это проверено в двух режимах: в `tdm` матч начинается только после `\ready` игроков, а в `ffa` он начинается сам, и `\ready` не нужен.

Подробно: [Начало матча в CPMA](cpma/README.md#начало-матча).

### Зашитое значение

Значение [переменной](#переменная-сервера), которое [entrypoint](#entrypoint) задаёт через [`+set`](#командная-строка-сервера) при каждом старте и для которого нет [ENV](#env), например `bot_enable 0`. Строка в [`autoexec.cfg`](#autoexeccfg) его не меняет, а [rcon](#rcon) меняет только до [рестарта контейнера](#рестарт-контейнера).

Подробно: [Зашитые значения](common/pinned.md).

### Игровой модуль

Файл `.qvm` с кодом игры или мода, например `qagame.qvm`. Сервер работает только с модулями образа: у stock [отказ](#отказ-при-старте) даёт свой `/data/home/demoq3/vm/qagame.qvm`, у CPMA и OSP свой `qagame.qvm`, `cgame.qvm` или `ui.qvm` в любом месте [тома home](#том).

Подробно: [Conflicting CPMA saved content](recipes/edit-env-and-files.md#conflicting-cpma-saved-content), [Чего не позволяет образ stock](stock/README.md#чего-образ-не-позволяет).

### Каталог игры

Каталог мода внутри `/opt/q3-data` и `/data/home`: `demoq3` у stock, `cpma` у CPMA, `osp` у OSP. Его задаёт [переменная](#переменная-сервера) `fs_game`, а в путях справочника он обозначен `<мод>`.

Подробно: [Каталоги](common/container.md#каталоги).

### Каталог карт

Файл `/app/maps.txt` в образе. В нём четыре колонки: карта, её [PK3](#pk3), режимы, в которых карта разрешена, и картинка для [лобби](#лобби). Карта из `maplist.txt` или `MAP` должна быть в нём, а у stock допустима ещё карта из своего PK3.

Подробно: [Посмотреть файлы игры](common/container.md#посмотреть-файлы-игры).

### Командная строка сервера

Аргументы, с которыми [entrypoint](#entrypoint) запускает [ioq3ded](#ioq3ded): `+set <переменная> <значение>` из [ENV](#env) и [зашитых значений](#зашитое-значение), `+exec` с [конфигом мода](#конфиг-мода) и `+map` со стартовой картой. У stock с несколькими картами вместо `+map` стоит `+exec rotation.cfg +vstr rotate1`. Движок применяет все `+set` до того, как выполнить `+exec` и `+map`, где бы они ни стояли в строке. Все `+set` он применяет после `default.cfg`, [`q3config_server.cfg`](#q3config_servercfg) и [`autoexec.cfg`](#autoexeccfg), поэтому `+set` побеждает строку в `autoexec.cfg`.

Подробно: [Как значение ENV попадает в игру](common/env.md#как-значение-env-попадает-в-игру), [Кто кого перекрывает](common/layers.md#кто-кого-перекрывает).

### Комната

Запись о сервере в [лобби](#лобби) под его [alias](#alias). Лобби показывает комнату карточкой с названием из `HOSTNAME`. Комнату держит [агент комнаты](#агент-комнаты), и при `RUN_ROOM_AGENT=0` её нет.

Подробно: [Состояния сервера и их признаки](common/network.md#состояния-сервера-и-их-признаки).

### Консоль сервера

Ввод команд прямо в [ioq3ded](#ioq3ded) через `docker attach`. Как подключиться к ней и как отключиться, не останавливая сервер, описано в рецепте.

Подробно: [Консоль сервера](recipes/console.md).

### Контейнер

Экземпляр [образа](#образ) Docker, в котором запускаются процессы сервера и к которому подключены [тома](#том). В примерах сервер работает в контейнере сервиса `q3ded` из `compose.yaml`.

Подробно: [Контейнер: компоненты, пути, тома](common/container.md).

### Конфиг мода

`cpma.cfg` у CPMA и `osp.cfg` у OSP: файлы образа, которые [entrypoint](#entrypoint) выполняет командой [`+exec`](#командная-строка-сервера) после всех `+set`. Они проверяются по хешу, и свой или изменённый файл останавливает запуск.

Подробно: [Конфиги, которые entrypoint выполняет после `+set`](common/pinned.md#конфиги-которые-entrypoint-выполняет-после-set).

### Лобби

Страница, где [комнаты](#комната) показаны карточками. Своё лобби есть у dos.zone, [dos.zone/mp/?lobby=q3](https://dos.zone/mp/index.html?lobby=q3), и у [стенда](#стенд) разработчиков. [Браузерный игрок](#браузерный-клиент) входит кнопкой Join на карточке. В лобби [агент комнаты](#агент-комнаты) публикует комнату сервера.

Подробно: [Признаки готовности](start.md#6-признаки-готовности), [Браузерный вход в OSP](osp/README.md#браузерный-вход), [CLOUD_BASE_URL](common/env.md#cloud_base_url).

### Манифест образа

Файл `/app/runtime-manifest.txt` с хешами файлов `/opt/q3-data`. CPMA и OSP сверяют с ним файлы при каждом старте, и изменённый файл образа даёт [отказ](#отказ-при-старте) `CPMA packaged data hash verification failed`.

Подробно: [Каталоги](common/container.md#каталоги).

### Мастер-сервер

Каталог серверов Quake III. Сервер с `PUBLISH_Q3_MASTER=1` публикуется в мастер-серверах из `Q3_MASTERS`, и его адрес есть в ответе мастера на запрос `getservers`.

Подробно: [Мастер-серверы](common/network.md#мастер-серверы).

### Мод

Модификация Quake III со своим [игровым модулем](#игровой-модуль) и файлами, например CPMA или OSP. В справочнике модом называют и вариант [образа](#образ), включая stock с обычной игрой: «Мод: все» значит stock, CPMA и OSP. `<мод>` в путях означает [каталог игры](#каталог-игры).

Подробно: [stock](stock/README.md), [CPMA](cpma/README.md), [OSP](osp/README.md).

### Образ

Образ Docker: неизменяемый пакет с программами и файлами, из которого Docker запускает [контейнер](#контейнер). Образы справочника лежат в `ghcr.io/doszoner/q3ded`, по одному на каждый [мод](#мод), а версию образа указывают [тегом](#тег) или [digest](#digest).

Подробно: [Образы](README.md#образы).

### Обычный клиент

Программа Quake III на компьютере игрока (проверен официальный ioquake3), которая подключается к серверу напрямую по [UDP](#udp) на `PORT`. Ей нужны `NATIVE_UDP=1` на сервере и все [PK3](#pk3) образа у игрока.

Подробно: [Файлы игры для обычного клиента](recipes/game-files.md).

### Отказ при старте

Остановка контейнера без запуска сервера: [entrypoint](#entrypoint) печатает причину последней строкой лога, по-английски, и выходит с кодом 1.

Подробно: [Отказы при старте](troubleshooting.md#отказы-при-старте).

### Переменная сервера

Именованная настройка [движка](#ioq3ded) или мода, по-английски cvar, например `sv_hostname` или `g_inactivity`. Её задают строкой `set` в конфиге, через `+set` в [командной строке сервера](#командная-строка-сервера) или через [rcon](#rcon), а имя переменной, введённое в [консоли](#консоль-сервера), печатает её текущее значение.

Подробно: [Консоль сервера: команды](troubleshooting.md#2-консоль-сервера).

### Пересоздание контейнера

Создание нового контейнера вместо прежнего: `docker compose up -d --force-recreate q3ded`, а после правки `compose.yaml` и обычный `docker compose up -d`. [Тома](#том) остаются прежними, изменённый [ENV](#env) применяется.

Подробно: [Почему не что-то другое](recipes/edit-env-and-files.md#почему-не-что-то-другое).

### Разминка

Время перед началом матча. У stock её включает `g_doWarmup`, у CPMA её задаёт [режим CPMA](#режим-мода) (параметр `warmup`), у OSP режим включает её по умолчанию.

Подробно: [Разбор строк, которые не применяются](common/layers.md#разбор-строк-которые-не-применяются).

### Режим игры

Вид матча, который задаёт [ENV](#env) `MODE`: `ffa`, `duel`, `tdm`, `ctf`, у CPMA и OSP ещё `ca` и `ftag`, у CPMA ещё `ctfs`. От него зависят `g_gametype`, тип [комнаты](#комната) в [лобби](#лобби) и карта по умолчанию. OSP пишет режимы в лог полными названиями: `Free-For-All`, `1v1`, `TeamplayDM`, `CTF`, `ClanArena`, `FreezeTag TDM`.

Подробно: [Простые ENV](common/env.md#простые-env).

### Режим мода

Набор настроек, который CPMA или OSP загружает при старте сервера по переменной `mode_start`, а её [entrypoint](#entrypoint) выбирает по `MODE` (у CPMA ещё по [`PRESET`](#preset)). Значения режима перекрывают [`autoexec.cfg`](#autoexeccfg) и [`+set`](#командная-строка-сервера). У OSP режим загружается примерно через 1,8 с после первого [`InitGame`](#initgame).

Подробно: [Кто кого перекрывает](common/layers.md#кто-кого-перекрывает).

### Рестарт контейнера

`docker compose restart`: тот же контейнер запускается заново. [Тома](#том) и [ENV](#env) остаются прежними, изменённый в `compose.yaml` ENV не применяется, а правка [смонтированного файла](#смонтированный-файл) применяется.

Подробно: [Почему не что-то другое](recipes/edit-env-and-files.md#почему-не-что-то-другое).

### Ротация карт

Смена карт по окончании матча в заданном порядке. У stock и CPMA порядок задаёт `maplist.txt`, OSP его не читает. Как задать список и как ротация работает у каждого мода, описано в рецепте.

Подробно: [Ротация карт](recipes/rotation.md).

### Сеть bridge

Подключение контейнера через сетевой мост Docker. [UDP](#udp) снаружи доходит до сервера только через проброс `ports:` с тем же номером, что и `PORT`. Эту сеть используют примеры справочника.

Подробно: [Соединения](common/network.md#соединения).

### Сеть хоста

`network_mode: host` без `ports:`: контейнер работает в сети хоста, и сервер слушает `PORT` прямо на [хосте](#хост). Так запускаются рабочие серверы [стенда](#стенд) разработчиков DosZone.

Подробно: [Сеть хоста](common/network.md#сеть-хоста).

### Смонтированный файл

Файл с хоста, подключённый в контейнер строкой `volumes:` в `compose.yaml` (bind-монтирование), например [`autoexec.cfg`](#autoexeccfg) или `maplist.txt` с пометкой `:ro`. Если такого файла на хосте нет, Docker создаёт на его месте пустой каталог.

Подробно: [Bind-монтирование отсутствующего файла](common/container.md#bind-монтирование-отсутствующего-файла).

### Стенд

Тестовый стенд разработчиков DosZone: отдельное [лобби](#лобби) и свой [peer-сервер](#peer-сервер). На нём проверяют сборки до выпуска.

Подробно: [Переход со стенда на dos.zone](recipes/stand-to-dozone.md#стенд).

### Судья

Роль игрока в CPMA с правом менять настройки матча, например лимит времени. Эти настройки действуют до конца карты. По умолчанию судьи нет.

Подробно: [Лимиты матча и судья](cpma/README.md#лимиты-матча-и-судья).

### Тег

Имя версии образа после двоеточия, например `20261112-d608e3a-stock` в `ghcr.io/doszoner/q3ded:20261112-d608e3a-stock`. Справочник проверен на тегах из таблицы образов.

Подробно: [Образы](README.md#образы), [Обновление тега](recipes/update-tag.md).

### Том

Хранилище Docker, которое переживает [рестарт](#рестарт-контейнера) и [пересоздание контейнера](#пересоздание-контейнера). У сервера два именованных тома: `/data/home` (том home, файлы [движка](#ioq3ded)) и `/data/run` (файлы [агента комнаты](#агент-комнаты)). Удаляет их `docker compose down -v`, после чего сервер стартует на новых томах.

Подробно: [Каталоги](common/container.md#каталоги).

### Физика игры

Набор игровых правил. Выбрать физику можно только в CPMA: их там две, [CPM](#cpm) и [VQ3](#vq3), и одну из них выбирает ENV `GAMEPLAY`.

Подробно: [GAMEPLAY](common/env.md#gameplay), [Физика VQ3 в CPMA](recipes/cpma-vq3.md).

### Хост

Машина, на которой работает Docker и запущен контейнер сервера. С хоста в контейнер монтируют файлы, а в firewall хоста открывают порт сервера для обычных клиентов.

Подробно: [Хост](start.md#1-хост).
