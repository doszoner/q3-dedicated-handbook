# Файлы игры для обычного клиента

[Мод](../glossary.md#мод): все. Проверено запуском на `20261112-d608e3a-stock`, `20261112-c64186e-cpma`, `20261114-9e899840-osp`: официальный ioquake3 с пустым домашним каталогом и полным набором файлов вошёл на сервер каждого мода.

Клиент нужен официальный ioquake3. Проверена сборка `1.36_GIT_8d2c2b4-2025-05-15` для Linux x86-64. Запускайте его всегда с `com_basegame q3-native-base`, а не `baseq3`: `pak0.pk3` в [образе](../glossary.md#образ) не из демо-версии id Software, и с `baseq3` клиент работает с ним неправильно. Каталог `q3-native-base` должен оставаться пустым.

## Что положить

Нужны **все** [PK3](../glossary.md#pk3) из `/opt/q3-data` образа, из всех подкаталогов, в одном каталоге мода внутри домашнего каталога клиента. На проверке эта сборка выбрала `~/.q3a` во всех четырёх проверенных условиях, среди них пустой домашний каталог, уже существующий `~/.config` и заданные `XDG_DATA_HOME` и `XDG_CONFIG_HOME`. Другая сборка может взять другой каталог; как это узнать, описано [ниже](#проверить-домашний-каталог-клиента).

| Мод | Каталог клиента | Сколько PK3 | Откуда в образе |
|---|---|---|---|
| [stock](../glossary.md#stock) | `~/.q3a/demoq3/` | 138 | `/opt/q3-data/demoq3/` |
| [CPMA](../glossary.md#cpma) | `~/.q3a/cpma/` | 150 | `/opt/q3-data/baseq3/` (148) и `/opt/q3-data/cpma/` (2) |
| [OSP](../glossary.md#osp) | `~/.q3a/osp/` | 14 | `/opt/q3-data/baseq3/` (5) и `/opt/q3-data/osp/` (9) |

Этот набор совпадает с манифестом клиентских файлов образа файл в файл, по sha256. С неполным набором клиент CPMA пишет `WARNING: You are missing some files referenced by the server`, с полным этого предупреждения нет.

Скопировать файлы из запущенного [контейнера](../glossary.md#контейнер), в каталоге с `compose.yaml` (пример для CPMA):

```sh
rm -rf ./q3-data
docker compose cp q3ded:/opt/q3-data ./q3-data
mkdir -p ~/.q3a/cpma
find ./q3-data -name '*.pk3' -exec cp -f {} ~/.q3a/cpma/ \;
ls ~/.q3a/cpma/*.pk3 | wc -l      # 150, если других PK3 там нет; повтор лишние PK3 не удаляет
```

`docker compose cp` копирует в `./q3-data` и файлы, которые вы [смонтировали](../glossary.md#смонтированный-файл) в `/opt/q3-data`, например [`autoexec.cfg`](../glossary.md#autoexeccfg) с `rconPassword`. В `~/.q3a` попадают только `*.pk3`, но `./q3-data` после копирования лучше удалить.

Копирование через `docker compose cp` и `find … -exec cp` проверено запуском на всех трёх модах, с заменой `cpma` на каталог мода: stock 138, CPMA 150, OSP 14 файлов, набор совпал с манифестом по sha256. С этими файлами клиент вошёл на сервер каждого мода. Блок целиком, с `rm -rf` и `cp -f`, проверен запуском на CPMA два раза подряд от обычного пользователя без sudo. Второй прогон заменил устаревший PK3 образа (в том числе файл только для чтения), все 150 файлов совпали с образом по sha256, а свой файл в `~/.q3a/cpma` (на проверке `my.cfg`) остался. Клиент с этим каталогом вошёл.

Без `-f` повторный `cp` не может перезаписать PK3 образа, потому что они только для чтения: `find` печатает `cp: cannot create regular file '…': Permission denied`, но всё равно завершается с кодом 0, и число файлов выглядит верным. PK3, которых в новом образе нет, команда не удаляет: они остаются в `~/.q3a/cpma` и попадают в подсчёт `wc -l`.

## Подключиться

Из каталога установки ioquake3:

```sh
./ioquake3.x86_64 +set com_basegame q3-native-base +set fs_game demoq3 +connect SERVER_IP:27960
./ioquake3.x86_64 +set com_basegame q3-native-base +set fs_game cpma +connect SERVER_IP:27960
./ioquake3.x86_64 +set com_basegame q3-native-base +set fs_game osp +connect SERVER_IP:27960
```

## Проверить домашний каталог клиента

Подключившись, введите в консоли клиента:

```
\path
\fs_homepath
```

`path` печатает `We are looking in the current search path:`, затем каталоги поиска. Среди них есть каталог мода в домашнем каталоге клиента, например `/home/you/.q3a/cpma`. У CPMA (`sv_pure 0`) он идёт первым, за ним ваши PK3. У stock и OSP (`sv_pure 1`) сначала идут PK3 (138 и 14), потом этот каталог. `fs_homepath` показывает сам домашний каталог; на проверке это был `~/.q3a`. Если там другой каталог, замените `~/.q3a` в командах копирования этим каталогом и повторите копирование.

## Результат

В логе сервера `ClientConnect: <N>`, затем `entered the game` (у CPMA `entered the arena`) и `ClientBegin: <N>`.

| Мод | Чистота (`sv_pure`) | Что клиент пишет, и это нормально |
|---|---|---|
| stock | 1: клиент проверяет все 138 PK3 | предупреждения о шейдерах `ospdm12` |
| CPMA | 0, так задумано в образе | предупреждения о шейдерах `ospdm12` |
| OSP | 1: клиент проверяет все 14 PK3 | предупреждения о шейдерах `ospdm12`, о `windfly.wav` и `music\fla22k_03` (последние два в одном коротком сеансе не появились) |

Клиент stock может сам скачать с сервера недостающую карту, которую оператор добавил своим PK3, см. [свои карты stock](stock-custom-maps.md#как-карта-попадает-к-игроку). Сервер CPMA файлы не раздаёт (`sv_allowDownload 0`), поэтому ставьте всё заранее.
