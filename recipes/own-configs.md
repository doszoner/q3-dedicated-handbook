# Свои конфиги для опытов

Эта страница для опытов со своими настройками. Сколько держится заданное значение, зависит от переменной и [жизненного цикла настройки](../common/layers.md#жизненный-цикл-настройки). Выполнение файла при каждом старте не отменяет [приоритет настроек образа и режима мода](../common/layers.md#кто-кого-перекрывает).

[Мод](../glossary.md#мод): все. Проверено запуском на `20261112-d608e3a-stock`, `20261112-c64186e-cpma` и `20261114-9e899840-osp`.

## Как файл попадает в контейнер

Сервер работает внутри [контейнера](../glossary.md#контейнер) и видит только его файлы. Файл с [вашей машины](../glossary.md#хост) сервер увидит, когда его подключат в контейнер. Подключение описывают в `compose.yaml`: внутри `services:` найдите `q3ded:`, а в нём раздел `volumes:`. В [примере CPMA](../examples/cpma/compose.yaml) этот раздел такой:

```yaml
    volumes:
      - run:/data/run
      - home:/data/home
      - ./maplist.txt:/data/maplist.txt:ro
      - ./autoexec.cfg:/opt/q3-data/cpma/autoexec.cfg:ro
```

Двоеточия разделяют части записи: сначала указано, что подключить, затем путь внутри контейнера. Пометка `:ro` в конце разрешает серверу только читать файл.

- `./autoexec.cfg:/opt/q3-data/cpma/autoexec.cfg:ro` подключает файл. Слева путь на вашей машине, `./` означает каталог, где лежит `compose.yaml`. Справа путь, по которому файл увидит сервер. В контейнере виден тот же файл, а не копия. Такой файл называют [смонтированным](../glossary.md#смонтированный-файл).
- `run:/data/run` и `home:/data/home` подключают [тома](../glossary.md#том): слева стоит имя тома, а не путь. Том хранит сам Docker, и при пересоздании контейнера его содержимое остаётся.

Какие ещё каталоги есть в контейнере и что в каждом лежит, описано в разделе [Каталоги](../common/container.md#каталоги). Изменённый раздел `volumes:` контейнер получает только при пересоздании, поэтому в рецепте ниже контейнер пересоздают.

## Положить файл

1. Рядом с `compose.yaml` создайте свой файл, например `my.cfg`:

   ```
   set g_inactivity 60
   ```

2. В `compose.yaml` добавьте в `volumes:` строку под строкой с [`autoexec.cfg`](../glossary.md#autoexeccfg). Вместо `cpma` впишите [каталог игры](../glossary.md#каталог-игры): `demoq3` у stock, `cpma` у CPMA, `osp` у OSP.

   ```yaml
         - ./my.cfg:/opt/q3-data/cpma/my.cfg:ro
   ```

3. Примените: `docker compose up -d --force-recreate q3ded`.

CPMA и OSP с таким файлом стартуют без [отказа](../glossary.md#отказ-при-старте): проверка хешей сверяет только файлы [образа](../glossary.md#образ), а ваш файл в их число не входит, см. [container.md](../common/container.md#каталоги).

## Выполнить один раз

На OSP сначала дождитесь в логе строки `Default mode "<режим>" enabled.` и второго [`InitGame`](../glossary.md#initgame), см. [две фазы старта OSP](../osp/README.md#сброс-при-инициализации-режима). Затем отправьте команду через [rcon](rcon.md):

```
/rcon exec my.cfg
```

Сервер отвечает `execing my.cfg`, в его логе появляется `Rcon from <адрес>: exec my.cfg`. Значение проверьте командой `/rcon g_inactivity`.

## Выполнять при каждом старте

1. Допишите в `autoexec.cfg` строку:

   ```
   exec my.cfg
   ```

2. Выполните `docker compose restart q3ded`.

В логе сразу после `execing autoexec.cfg` идёт строка `execing my.cfg`, и значения из файла действуют без rcon. Проверено двумя [рестартами](../glossary.md#рестарт-контейнера) подряд на каждом моде.

Значения из `my.cfg` при этом перекрываются настройками, которые образ задаёт через `+set`, [конфиг мода](../glossary.md#конфиг-мода) или режим мода (CPMA, OSP): эти настройки применяются после `autoexec.cfg`, см. [порядок слоёв](../common/layers.md#кто-кого-перекрывает) и [зашитые значения](../common/pinned.md). На stock со строкой `set g_allowVote 1` в `my.cfg` после старта `g_allowVote` был `0`, после rcon `exec my.cfg` стал `1`, а после следующего рестарта снова `0`.

## Правка без рестарта

Поправьте `my.cfg` на [хосте](../glossary.md#хост) и снова выполните `/rcon exec my.cfg`: сервер прочитает новый текст без рестарта. Проверено запуском на всех трёх модах, файл переписывали на месте (`printf … > my.cfg`).

Если редактор сохраняет файл заменой (так делает `sed -i`), внутри [контейнера](../glossary.md#контейнер) остаётся старый текст. На stock после `sed -i` rcon `exec my.cfg` выполнил прежние значения. Тогда нужен `docker compose restart q3ded`, см. [примечания](../common/layers.md#примечания).

## Файл в томе home

Вместо монтирования файл можно скопировать в каталог `/data/home` работающего контейнера:

```sh
mod=cpma    # ваш каталог игры: demoq3, cpma или osp
docker compose cp my.cfg "q3ded:/data/home/$mod/my.cfg"
```

После `docker compose restart q3ded` все три мода стартуют без отказа, и rcon `exec my.cfg` выполняет этот файл. Если файл с тем же именем [смонтирован](../glossary.md#смонтированный-файл) и в `/opt/q3-data/<мод>`, выполняется копия из `/data/home`, см. [какой файл читается](../common/layers.md#какой-файл-читается). Удалить копию можно так:

```sh
docker compose run --rm --no-deps --entrypoint rm q3ded "/data/home/$mod/my.cfg"
```

## Сколько держатся значения

- После rcon `exec my.cfg` значения ведут себя как заданные через rcon. На проверке значения, заданные в файле через `set`, пропали после `docker compose restart`. Что переживает рестарт, расписано в [жизненном цикле настройки](../common/layers.md#жизненный-цикл-настройки).
- Строка `exec my.cfg` в `autoexec.cfg` выполняет файл при каждом старте, как и сам `autoexec.cfg`.
- Копия в `/data/home` лежит в [томе](../glossary.md#том) и пропадает вместе с ним (`down -v`), так же как `autoexec.cfg` в `/data/home` в [таблицах жизненного цикла](../common/layers.md#жизненный-цикл-настройки).

## Что образ не примет

- Какие файлы в `/data/home` вызывают отказ, перечислено в рецепте [Conflicting CPMA saved content](edit-env-and-files.md#conflicting-cpma-saved-content).
- Проверка файлов образа в `/opt/q3-data` описана в разделе [о каталогах контейнера](../common/container.md#каталоги).
- Остальное перечислено в разделах «Чего образ не позволяет» для [stock](../stock/README.md#чего-образ-не-позволяет), [CPMA](../cpma/README.md#чего-образ-не-позволяет) и [OSP](../osp/README.md#чего-образ-не-позволяет).

## Свой файл режима CPMA

Файл режима, смонтированный в `/opt/q3-data/cpma/modes/MYFFA.cfg`, запуск CPMA не останавливает. Загрузить его не удалось: rcon `mode MYFFA` вернул пустой ответ, а `mode_current` остался `FFA`. Голосование за такой режим не проверялось.
